Getting started

What is still missing before Claude Desktop can talk to the proxy.

    API keys

    Written to .env in the project root. Existing keys are shown masked — leave a field empty to keep the current one.

    Text provider

    With more than one key configured the proxy follows the priority OpenCode Go → OpenRouter → GLM → DeepSeek → Google AI Studio, with custom providers last. Pin one here to override that order. Images go to Google either way — straight to it when it is the text backend, through OCR otherwise.

    Custom providers

    Anything that speaks the OpenAI API — Ollama, LM Studio, vLLM, llama.cpp, a company gateway. Point it at the base that holds /chat/completions and /models, usually ending in /v1. A local server needs no key; leave it empty.

    Known bases: Ollama :11434/v1 · LM Studio :1234/v1

    Proxy port

    Changing the port does not require reissuing the certificates, but Claude Desktop has to point at the new URL — use Write configuration under Diagnostics after saving.

    Models by provider

    With discovery on, the proxy asks that provider for its model list at startup (and every 30 min) and names each model automatically — haiku for the free and cheap ones, sonnet up to $2/M, opus above that, fable when there is no price data. Those are the families Claude Desktop accepts; the version part is free. With discovery off, only the static maps in proxy/server.js apply. Uncheck anything you do not want in the model picker, and hover an id to rename it — a rename is kept across refreshes.

    Claude Desktop only accepts ids in its own families — claude-haiku-…, claude-sonnet-…, claude-opus-…, claude-fable-… and claude-mythos-… — so anything else is refused. The version part is free, and Patchbay numbers ten models per version (claude-opus-3 through claude-opus-3-9, then claude-opus-4). Ids are renumbered whenever the selection changes; use the padlock to keep one where it is.
